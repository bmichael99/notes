The EventTypes table defines all possible event types that can occur in the FOMS system. Each event type has a unique handle, friendly name, and metadata that controls how events are processed and displayed.

Event types are created automatically when new events are logged, but can also be pre-defined for better organization and to set properties like whether they require approval or are system events.
# Categories
- **order_management**: Events related to order lifecycle
- **inventory**: Events related to inventory changes
- **shipping**: Events related to shipments and delivery
- **system**: Automated system operations
- **user_action**: Manual user operations
# System vs User Events
- `is_system_event = TRUE`: Events generated by automated processes (imports, cron jobs)
- `is_system_event = FALSE`: Events generated by user actions or external systems
# Approval Requirements
- `requires_approval = TRUE`: Events that may need admin review (high-value changes, errors)
- `requires_approval = FALSE`: Standard operational events
# Create Table Syntax
```sql
CREATE TABLE IF NOT EXISTS EventTypes (
    id INT AUTO_INCREMENT PRIMARY KEY,
    handle VARCHAR(100) NOT NULL UNIQUE,
    friendly_name VARCHAR(255) NOT NULL,
    description TEXT,
    category VARCHAR(50),
    is_system_event BOOLEAN DEFAULT FALSE,
    requires_approval BOOLEAN DEFAULT FALSE,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,

    INDEX idx_handle (handle),
    INDEX idx_category (category),
    INDEX idx_system_event (is_system_event)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```
# Common Event Types

## Order Management Events
- `order_imported`: Order successfully imported from external source
- `destination_submitted`: Order submitted to fulfillment destination
- `destination_confirmed`: Order confirmed at fulfillment destination
- `destination_confirm_failed`: Failed to confirm order at destination
- `status_changed`: Order status manually changed
## Automated Events
- `destination_submitted_automated`: Order auto-submitted by cron
- `destination_confirmed_automated`: Order auto-confirmed by cron
- `destination_confirm_not_found`: Order not found during auto-confirmation
- `destination_confirm_failed_automated`: Auto-confirmation failed
## Line Item Events
- `line_item_added`: Line item added to order
- `line_item_updated`: Line item quantity/price changed
- `line_item_removed`: Line item removed from order
# Queries
Get all event types by category:
```sql
SELECT * FROM EventTypes
WHERE category = ?
ORDER BY friendly_name;
```
Find event types that require approval:
```sql
SELECT * FROM EventTypes
WHERE requires_approval = TRUE
ORDER BY category, friendly_name;
```
Search event types by name:
```sql
SELECT * FROM EventTypes
WHERE friendly_name LIKE CONCAT('%', ?, '%')
	OR handle LIKE CONCAT('%', ?, '%')
	OR description LIKE CONCAT('%', ?, '%')
ORDER BY friendly_name;
```
Count events by type over time:
```sql
SELECT et.friendly_name, COUNT(e.id) as event_count
FROM EventTypes et
	LEFT JOIN Events e ON et.handle = e.event_handle
WHERE e.timestamp >= DATE_SUB(NOW(), INTERVAL 30 DAY)
GROUP BY et.id, et.friendly_name
ORDER BY event_count DESC;
```
